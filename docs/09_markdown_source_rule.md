# 本文Markdownの正本規則と、紙面HTMLへの反映

更新日：2026-09-23。

## 正本

記事本文の正本は、各記事フォルダの現行 `.md` です。HTMLは本文の正本ではありません。

```text
企画.md              記事設計・構成メモ
記事名.md            本文の正本
記事名.html          中間HTML
fixed_layout.html    固定紙面HTML
fixed_layout.css     紙面CSS。存在する場合
画像ファイル         採用した画像素材
```

本文を書く・直す場合は、現行の本文Markdownを変更します。HTMLだけを変更して本文更新済みと扱いません。`backup/` や `過去版/` は履歴・比較用であり、現行本文の代わりにはしません。

## レイアウト調整との区別

配置、余白、フォント指定、画像のトリミング、ページ境界などの紙面調整は、HTML/CSS側の作業です。それによって本文の正本がHTMLへ移るわけではありません。

本文や見出し、キャプション、本文画像の採用内容を変える場合は、Markdownと画像配置記録等の該当する正本にも反映します。CSS調整のために原稿を別ファイルへコピーし、二つの本文を独立管理する方式にはしません。

## 自動同期があるという意味ではない

この規則は、Markdownから固定HTMLへの自動変換が実装済みであるという宣言ではありません。

2026-09-23に確認した `tools/build_article.mjs` は、既存の固定HTMLを開いてPNGにし、Markdownがあれば中間フォルダへコピーします。Markdownを解析して紙面HTMLへ変換する処理ではありません。CodeSwing用・Pages用ビューアーも既存HTMLを表示するだけです。

したがって次は別々の状態です。

```text
本文Markdownを修正した
素材画像を配置した
固定HTMLへ反映した
HTMLの表示を確認した
PNGの出力を確認した
記事が承認・校了した
```

一つが完了しても、残りを自動的に完了へ進めません。とくにMarkdownの画像参照が更新されても、固定HTMLが古い候補画像を読んでいる場合があります。

## 反映作業で残す情報

対象の記事と本文の版、変更した内容、反映先のHTML/CSS、参照する画像、表示を確認した環境を記録します。全号へ展開する前に記事単位で比較します。

将来、変換を自動化する場合は、本文・テンプレート・資産の対応と再生成時に保持するレイアウト指定を決めます。ソースハッシュ等の同期検査は改善案であり、既存manifestが既に保証している機能ではありません。
