## 対象と現在地

最初の適用対象は `202604/04_聖職者花見乱痴気騒ぎ/` です。現行の本文45ブロックと採用画像5点を読み、固定HTMLと1456×2056のPNG6ページを生成しました。本文・画像ファイル・採否は変更していません。記事の編集状態も `REWRITTEN_PENDING_USER` のままです。全号の同期や校了ではありません。

本文の一部を独立して手入れする二重管理はしません。`layout-source.json` が正本Markdownとテンプレートを指定し、`fixed_layout.html` はその派生物です。HTMLは生成プログラム・CSS・組版処理・原稿・選択画像・フォントのSHA-256を内包します。`build_article.mjs` は現在の入力から期待HTMLを再計算し、違えば出力を止めます。

## 操作

Node、Playwright Chromiumを使う環境のリポジトリ直下で実行します。通常のvscode.dev単体ではこれらのコマンドを実行できません。

```bash
node tools/sync_article_layout.mjs "202604/04_聖職者花見乱痴気騒ぎ" --check-only
node tools/sync_article_layout.mjs "202604/04_聖職者花見乱痴気騒ぎ"
node tools/build_article.mjs "202604/04_聖職者花見乱痴気騒ぎ"
```

一つ目は最新原稿から候補HTMLをメモリ上に生成し、資産・内容・面積比・重なり・余白を実測します。記事へ書き込みません。既存HTMLが古くても、生成予定の紙面を検査できます。

二つ目も同じ検査を実施し、成功時だけ `fixed_layout.html` を置き換えます。画像・フォントの欠落、未対応記法、入らない見出し、検査失敗時には古いHTML・PNGを保持します。検査中に入力が変わった場合も止めます。

三つ目は同期済みHTMLを再検査してPNGを出し、`pages/` と `intermediate/` を更新します。HTMLの同期とPNG生成は別トランザクションです。同期後にPNG生成が失敗した場合は、HTMLが新しくPNGが旧版のままになります。`article_manifest.json` の `sourceSync.htmlSha256` と `pages[].sha256` を照合し、ファイルの存在だけで同版と判断しません。号全体の旧収集処理には、この照合は未実装です。

直下プレビューの記事選択に「04 聖職者花見乱痴気騒ぎ」を追加しました。「保存後に再読込」で、原稿・画像・フォント・テンプレートの実ファイルと埋込ハッシュを照合します。不一致なら古い紙面を表示せず、再組版が必要なファイルを示します。生成後に固定HTML自体を手編集した場合も、生成時のハッシュとの不一致で停止します。再読込の間にファイルを変更した場合まで監視するファイルシステム通知ではありません。

既存の `build_article --check-only` は、現在保存されているHTMLの検査です。最新原稿から候補を組む `sync_article_layout --check-only` とは役割が異なります。既存の表紙・制服名鑑は `legacy-untracked` と記録し、同期済みとは呼びません。

## このテンプレートで扱う原稿

先頭のh1とh2を記事タイトルと副題とし、その後のh2を節境界にします。各節は採用画像を一つ持ちます。本文・引用・見出し・表・`figure` 内の画像とキャプションを扱います。figureは現行原稿の属性・構造に限定し、任意のHTMLやスクリプトを通しません。太字、リンク、リスト、一般的なMarkdown画像など未対応の記法は行番号付きで停止します。未対応の要素を黙って平文へ変えたり捨てたりしません。

採用画像を節の上部へ配置し、その節の文章を原稿順に流します。原稿中のfigureの前後位置をそのまま行単位で再現する方式ではありません。節と画像の対応は保ち、別候補を推測して採用しません。画像は `object-fit:contain` で全体を表示します。

段落はまず丸ごと置きます。新しいページにも入らない場合は、表示できる文字範囲を実測し、可能なら文末で分割します。Unicodeコードポイントの途中で分割しません。表は行単位で分割し、続きのページにヘッダーを再掲します。見出しは直後の本文または表の最初の行と一緒に置き、孤立させません。画像とキャプションは一体です。続きのページでは同じ節の採用画像を再掲し、再掲を新規画像点数へ加算しません。

花見記事では三本角の料理画像だけを二度配置しています。5点の独立画像で6ページです。本文の文字列、表の行とセル、画像・alt・キャプションは原稿ブロックIDで照合し、削除・重複・並び違い・分割範囲の欠落を検査します。読みやすさや意味の正しさ、記事承認はこの照合とは別です。

## 余白と画像優位の検査

紙面外寸は1456×2056、左右の基本余白は64pxです。本文は28px・行高42pxで縮小せず、本文下端は1936px以内とし、ノンブルと離します。画像・キャプション・柱・本文・ノンブルの矩形の順序と重なりを検査します。共通の紙面検査を併用し、外周28px以上、要素・文字行の切れを確認します。

画像面積はcontain後に実際に表示する元画像の矩形です。縦長画像の左右の空白は数えません。文字面積は本文ブロック、表全体、見出し、キャプション、柱、ノンブルの矩形面積の合計です。文字ブロック内の空白も含める保守的な評価です。各ページで画像面積がこの文字面積を超えるまで配置を抑え、超える内容は画像付きの次ページへ送ります。

実測した画像／文字面積比はページ順に約1.81、1.62、1.31、1.35、1.09、1.15です。有効誌面の画像60〜70％という制作上の目安を全ページで達成したとはしていません。画像内部の看板等に描かれた文字の面積は自動抽出していないため、この比率は外部本文と画像枠の評価です。画像内部の文字を含む厳密な面積判定は目視の残件です。

今回のテンプレートは影・疑似要素・maskを使わず、柱・ノンブルもDOM要素として計測します。実記事の共通検査はerror・warningとも0件でした。任意のCSSやフォントに一般化した絶対安全保証ではありません。

## フォントと再現性

Noto Sans CJK JP Regularから作成した473コードポイントのWOFFサブセットを記事の `fonts/` へ保存し、HTMLへ埋め込みます。元フォントの著作権・OFL全文・出所・SHA-256を同梱しています。派生フォント名は `IsekaiArticleSubset` です。OSの代替フォントで黙って組版を続けず、原稿に未収録の文字が追加された場合は生成を停止します。

必要な場合だけ、指定した元フォントから再作成します。通常の組版・PNG出力にはPythonは不要です。

```bash
python tools/subset_article_font.py /path/to/NotoSansCJKjp-Regular.otf "202604/04_聖職者花見乱痴気騒ぎ"
```

再作成はPythonとfontToolsが必要です。サブセットを更新したらHTMLも再同期します。元フォントは自動取得せず、指定ファイルのハッシュを記録します。

今回の検証環境はLinux、Node v24.19.0、Playwright 1.60.0、Chromium 133.0.6943.0、DPR 1です。ブラウザ実行環境を配布物へ固定する仕組みまでは追加していません。他環境でも毎回実測して合否を判定しますが、同じ改ページ・同じ画素になるとは保証しません。
