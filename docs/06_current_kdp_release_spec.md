
## 3. ビルド手順

現状、補助アセットを確実に反映するには、通常ビルド前に以下を実行する。

```bash
node tools/patch_fixed_layout_head_assets.mjs
node tools/sync_fixed_layout_sources.mjs
node tools/check_fixed_layout_sources.mjs
node tools/validate_fixed_layout_geometry.mjs
node tools/export_fixed_layout_images.mjs
node tools/prepare_kindle_pages.mjs
python tools/build_fixed_layout_epub.py
python tools/check_fixed_layout_outputs.py
```

### 注意

`tools/build_fixed_layout_all.mjs` だけでは、追加した補助CSS/JSが必ず反映されるとは限らない。

現状では、ビルド前に `patch_fixed_layout_head_assets.mjs` を挟む運用とする。

## 4. 固定レイアウト検証仕様

詳細は以下を参照。

```text
docs/04_fixed_layout_measurement_spec.md
docs/05_fixed_layout_design_capacity_spec.md
```

要点：

```text
PAGE_W = 1456
PAGE_H = 2056
EPS = 1
BLEED = 24
```

`tools/validate_fixed_layout_geometry.mjs` は `.fixed-page` 内の全DOM要素を `getBoundingClientRect()` で検査する。

斜めDOM要素・回転DOM要素は、変形後の外接バウンディングボックスで判定する。

ただし、CSS疑似要素 `::before` / `::after` はDOM要素ではないため、通常のDOM検査では直接検出できない。検査不能な疑似装飾は避けるか、実DOM化する。

## 5. 現状の補助アセット

### 5.1 画像拡大用JS

```text
tools/fixed_layout_image_expand.js
```

目的：

```text
ページ確定後、ページ内に余白がある場合、画像入りパッケージの --image-max-height を最大960pxまで拡張する。
```

前提：

```text
fixed_layout.html の head に script として読み込む必要がある。
```

### 5.2 実測向け上書きCSS

```text
tools/fixed_layout_measured_overrides.css
```

目的：

```text
検査不能な疑似要素装飾を無効化し、DOM検査の対象外になる斜め帯などを出力から外す。
```

前提：

```text
fixed_layout.html の head に stylesheet として読み込む必要がある。
```

### 5.3 head注入スクリプト

```text
tools/patch_fixed_layout_head_assets.mjs
```

目的：

```text
01_聖女泥酔スクープ記事/fixed_layout.html に、補助CSSと補助JSの読み込みを追加する。
```

この後、`sync_fixed_layout_sources.mjs` によって全記事へ同期する。

## 6. KDP販売価格方針

現状サイズは約80MB。

販売価格の目安：

```text
試験価格: 300円
弱め通常価格: 480円
推奨価格: 680円
強気価格: 780円
980円以上: 現状では早い
```

現状の推奨：

```text
通常価格: 780円
発売記念価格: 680円
```

または、迷う場合は最初から：

```text
680円
```

理由：

```text
- 画像主体の固定レイアウトEPUBである
- 80MB級のため、低価格にしすぎると手残りが弱い
- 単号の雑誌風商品としてはワンコイン超え程度が自然
- 980円以上はレビュー・シリーズ継続・外部導線が整ってから
```

## 11. 現状の注意点

```text
- 補助CSS/JSは追加済みだが、通常ビルドに完全統合されていない。
- ビルド前に patch_fixed_layout_head_assets.mjs を実行する必要がある。
- 疑似要素装飾はDOM検査に乗らないため、今後は実DOM化するか、疑似要素を使わない。
- 内容紹介は実話誌風でよいが、実在事件・犯罪実録・ノンフィクションと誤認される表現は避ける。
```
